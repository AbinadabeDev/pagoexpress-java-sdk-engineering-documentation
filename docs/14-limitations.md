# Limitations and Public Boundaries

## Why this repository does not contain code

The implementation is client-owned proprietary software.

The repository therefore prioritizes engineering transparency without source disclosure.

## What the documentation can demonstrate

It can demonstrate:

- understanding of the problem;
- system boundaries;
- architecture;
- API integration reasoning;
- payment-domain reasoning;
- authentication concerns;
- error-handling design;
- testing strategy;
- security considerations;
- design decisions;
- trade-offs;
- professional handling of client intellectual property.

## What the documentation cannot prove by itself

Without publishing proprietary implementation, this repository cannot allow an external reader to:

- compile the original SDK;
- inspect original classes;
- review original commits;
- run original tests;
- verify private API payloads.

That limitation is intentional.

## Why synthetic examples are used

Synthetic examples demonstrate concepts without reproducing client implementation.

They must never be represented as exact copies of production code.

## Private API details

Exact private endpoint paths, payloads, headers and status contracts are omitted.

The goal of the portfolio is to demonstrate engineering capability, not to recreate the client's private API documentation.
